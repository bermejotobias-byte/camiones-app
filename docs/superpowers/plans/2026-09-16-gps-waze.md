# GPS con la piel de Waze — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** dejar la pantalla del mapa con la estructura, las medidas y los colores del prototipo aprobado, sobre una lógica de ruteo que nunca ofrece ni avisa lo que el motor ya excluyó.

**Architecture:** primero el servidor (hazards desde la ruta, evaluador coherente, rutas bloqueadas que no se ofrecen), después la piel por pantallas: `navigate.js` queda como anfitrión y cada superficie vive en `wwwroot/js/mapa/*.js`; los tokens del GPS y del mapa van a `app.css` bajo `--gps-*` y `--map-*`; el estilo de MapLibre se arma en `estilo-mapa.js`.

**Tech Stack:** .NET 10 Minimal API + EF Core, xUnit; módulos ES nativos sin empaquetador, MapLibre GL, `node --test`.

**Spec:** `docs/superpowers/specs/2026-09-16-gps-waze-design.md` · **Prototipo:** `docs/diseno/prototipo-gps/`

## Global Constraints

- Un dp del prototipo es un px de CSS; las medidas y los colores de la spec §2 se copian textuales, no se redondean.
- Roboto (`system-ui`) sólo dentro de `.map-screen`; Nunito en el resto.
- Ninguna ruta lleva rojo; el rojo queda para la chapa de un gálibo que el camión no pasa.
- No se rutea por ejes ni se inventa tráfico ni límite de velocidad: donde falta el dato, se dice.
- TDD estricto: cada test se ve fallar antes del código. Un commit por tarea. Parar el backend antes de `dotnet test`.
- `routing/config-truck.yml` no se commitea nunca.

```csharp
public static class RouteOffer
{
    /// <summary>Una ruta es ofrecible si ningun tramo esta prohibido para el camion.</summary>

        route.RestrictionNotes.All(n => n.RequiresAccessException);

    /// <summary>La recomendada y las alternativas que se pueden ofrecer; null si la recomendada no se puede.</summary>
    public static IReadOnlyList<TruckRoute>? Offerable(IReadOnlyList<TruckRoute> routes) =>

}
```
